# 03｜开发路线与验收标准

开发策略：按可使用的纵向闭环交付，不按“先画完所有页面、再写所有后端”横向铺开。每个阶段都必须有可运行环境、真实数据库、测试与移动端验收。

## Phase 0｜V2 独立底座与设计准备

目标：确保 V1 零影响，并把静态 Figma 变成可实施的组件与流程基线。

工作：

- 新建独立 GitHub 仓库、Vercel 和 Supabase 项目，配置 preview/staging/production。
- 建立 pnpm monorepo、代码质量、测试和 CI。
- 从 V1 迁移领域测试，不迁移 `app.js` 和 localStorage store。
- 整理 Figma：8 个业务屏幕改为顶层画板，建立变量、组件和 Prototype 连线。
- 新增登录、创建/加入小屋、加载/空/错/离线、AI 确认单等必要状态的设计清单。

验收：

- V1 工作树与线上链接无变化。
- V2 preview 可打开，拥有独立环境变量与空数据库。
- V1 的 26 个核心行为在 V2 domain 测试中继续通过。
- Figma 的核心路径可点击预览，不再只是静态拼图。

## Phase 1｜真实多人小屋

目标：两名真实账号能在不同设备加入同一小屋并看到相同数据。

工作：

- 邮箱 OTP 登录、个人资料、创建小屋、邀请链接、加入/退出。
- Owner/Admin/Member 权限和 RLS。
- 小屋切换、成员列表、活动记录基础。
- Realtime 私有频道与查询失效。

验收：

- 未加入小屋的账号无法通过前端或直接 API 读取数据。
- 邀请过期、重复使用和移除成员均有自动化测试。
- 两台设备上的成员变化能同步，刷新后结果一致。

## Phase 2｜费用闭环（第一个价值闭环）

目标：从记录费用到双方确认结清可完整使用。

工作：

- 手动记账、四种分摊、整数分核对、费用详情。
- 净余额、建议转账、部分结算、结算双方确认。
- 作废/冲正、历史、活动与通知。
- 两人并发、重复提交、网络重试保护。

验收：

- 任意合法分摊都满足分摊之和等于费用总额、全屋净余额之和为零。
- 结算分配不超过未结金额；幂等重放不产生重复费用或结算。
- Playwright 使用两个独立账号完成“记账→结算→确认→结清”。

## Phase 3｜家务闭环

目标：周期任务不再依靠群聊提醒与人工轮换。

工作：

- 一次性/周期模板、本周排班、到期与逾期。
- 完成、撤销、转交/接受、跳过、自动下一轮。
- 安静时段和提醒偏好。

验收：

- 周期完成只生成一个下一轮实例，负责人按规则轮换。
- 转交必须由明确接手人接受；冲突操作不静默覆盖。
- 提醒任务可重放且不重复发送。

## Phase 4｜用品闭环

目标：从发现缺货到补货和共同费用一次完成。

工作：

- 用品、库存阈值、消耗/校准流水、缺货优先视图。
- 唯一认领、取消、采购完成、入库。
- 采购记录与共同费用原子关联。

验收：

- 同一物品同时只能有一个有效采购认领。
- 采购重试不会重复入库或重复生成费用。
- 用品状态可由库存事实重新计算，不依赖手写状态字符串。

## Phase 5｜PWA 与通知

目标：像 App 一样从手机桌面进入，并在不打扰的前提下获得提醒。

工作：

- Manifest、图标、安全区、Service Worker、安装指引。
- 最近同步内容的只读离线视图和本机草稿。
- Web Push、通知分类、安静时段、深链。

验收：

- Android Chrome 与 iOS Safari 均完成真实设备安装检查。
- 离线时不允许把未校验的账务写成已确认。
- 推送点击能进入对应费用、家务或用品详情。

## Phase 6｜AI Native 纵向能力

顺序：自然语言记账 → 复杂分摊 → 小票 → 家务 → 用品。先把一个能力做可靠，再扩工具面。

工作：

- Proposal schema、提示版本、工具契约、确认策略。
- 费用自然语言解析与可编辑确认单。
- 图片输入与小票条目选择。
- 家务和用品的上下文操作。
- 运行日志、字段纠正与评估数据采集。

验收：

- 模型永远不能直接写核心业务表。
- 所有写操作都经过最新快照的确定性校验；重要操作有确认证据。
- AI 不可用时，人工流程仍完整可用。
- 固定评估集通过预设门槛后才能更换模型或提示版本。

## Phase 7｜分析、用户测试与 Beta

目标：用真实、可解释的数据决定下一轮，不用虚构成绩证明产品。

工作：

- 埋点质量校验、漏斗/留存/闭环报表。
- 招募真实合租小屋进行任务测试与日记研究。
- 反馈入口、问题分级、隐私与数据删除流程。
- 性能、安全、可访问性和故障演练。

验收：

- 生产事件与测试事件可完全分离。
- 每个指标能追溯到事件定义和查询版本。
- 测试报告只包含真实参与者、真实任务和观察，不填充虚构样本。
- 上线清单、回滚方案、数据备份与删除验证完成。

## 第一轮建议里程碑

第一轮只交付 Phase 0–2：一个可安装但写操作要求联网的移动 Web、真实账号与小屋、完整费用闭环。这样最早验证“室友是否愿意共同使用同一份账”，再继续投入家务、用品和 AI。
